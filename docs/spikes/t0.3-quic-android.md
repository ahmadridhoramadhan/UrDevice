# Spike T0.3: QUIC between Android and a desktop on real Wi-Fi

Date: 18 November 2026. Result: **works**; no design change needed.

## Setup

| | Device |
|---|---|
| Desktop | Ubuntu (GNOME), wired Ethernet to the router, `192.168.18.13` |
| Phone | vivo I2505, Android 16 (API 36), Wi-Fi to the same router, `192.168.18.23` |
| Build | Debug builds of this branch; the app targets API 37 |

## What was checked

| Check | Result |
|---|---|
| UDP broadcast discovery (port 47810) in both directions | Each device listed the other on the Pair screen within one announce interval (≤ 5 s); usually at once, because opening the Pair screen announces immediately |
| NsdManager on Android with a `MulticastLock` | Registers `_urdevice._udp`, and the core receives resolved addresses through `add_discovered` |
| QUIC with mutual TLS 1.3, Ed25519 certificates (rustls + ring on arm64) | Handshake completes; pinned keys verified on both sides |
| Code pairing over Wi-Fi | Both screens showed the same code (`638 962`); paired after "Codes match" on both |
| Automatic reconnect after restarting both apps | Session open about 1 s after start |
| Permission push | A Deny set on the phone greyed out the tile on the desktop in under 0.6 s |

## Round-trip time

quinn's smoothed RTT, sampled every second for 60 s on an idle session (only keep-alives):

| Phone state | n | min | median | p95 | max |
|---|---|---|---|---|---|
| App in the foreground, screen on | 61 | 16.3 ms | 21.8 ms | 26.5 ms | 29.1 ms |
| App in the background | 65 | 32.1 ms | 44.7 ms | 63.0 ms | 63.0 ms |

With the UI open and traffic flowing, the device view showed 5–13 ms. The idle numbers are higher because quinn's estimate includes the peer's ACK delay and the phone's Wi-Fi power saving between keep-alives. The input latency target (R9.5, < 50 ms p95) should be measured again in T4.9 with real input traffic.

## Notes for later phases

- Android 17 (API 37) blocks LAN traffic for apps that target it unless the user grants `ACCESS_LOCAL_NETWORK`. The app declares it and asks on API 37+; this phone (API 36) did not need it.
- The desktop also has Docker and libvirt bridges. QR invites and broadcast targets skip `docker*`, `br-*`, `veth*`, `virbr*`, and similar interfaces, or the phone would try unreachable addresses first.
