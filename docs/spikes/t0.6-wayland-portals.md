# Spike T0.6: Wayland RemoteDesktop and ScreenCast portals

Date: 19 November 2026. Result: **GNOME works** (tested on this machine), **KDE Plasma works** (from KDE's documentation; not tested here). wlroots-based compositors (Sway, Hyprland) have ScreenCast but no RemoteDesktop portal, so input there needs the `uinput` fallback.

## Test on GNOME

| | |
|---|---|
| Machine | Ubuntu, GNOME Shell 50.1 on Wayland, one 1920x1080 screen |
| Portal | `xdg-desktop-portal` 1.21.1, `xdg-desktop-portal-gnome` 50.0 |
| Caller | A host (non-sandboxed) script over D-Bus, the way the desktop app will call the portal |

Steps: `RemoteDesktop.CreateSession`, `SelectDevices` (keyboard and pointer, `persist_mode` = 2), `ScreenCast.SelectSources` (one monitor, embedded cursor), `RemoteDesktop.Start`, then `NotifyPointerMotion` 40 px right and back, a check that the PipeWire node exists, and `Session.Close`.

| Check | Result |
|---|---|
| Portal versions | RemoteDesktop v2 (keyboard, pointer, touchscreen); ScreenCast v5 (monitor, window, virtual; hidden, embedded, and metadata cursor) |
| First `Start` | GNOME shows one dialog for screen and input together. Approved by the user in about 4 s |
| Pointer through the portal | Moved and came back |
| Screen stream | PipeWire node `Stream/Output/Video` from `gnome-shell`, 1920x1080, 4 formats offered |
| `restore_token` | Returned on every `Start` |
| Second session with the token | No dialog; `Start` answered in under 0.1 s |

A restore token lets the app start screen capture and input again **without** any dialog. So UrDevice's own rules are the only gate after the first approval:

- Remote control and Screen sharing still follow the R5 setting on this device (Always Ask by default), and the indicator and Stop button stay on (R5.4).
- The token is a secret: keep it in the OS keystore, never in logs, and delete it on "Delete all data" and "Reset identity".
- A new token comes back on each `Start`; store the newest one. If restoring fails, fall back to the dialog.

## `uinput` fallback

- `uinput` creates a virtual keyboard and mouse in the kernel. It works on any compositor, but it needs write access to `/dev/uinput`.
- On this Ubuntu machine the logged-in user already has an ACL on `/dev/uinput`. Other distributions often allow only root. The app checks access first and offers the udev rule only when it is missing (R9.2, design §9.3).
- `uinput` moves the pointer by relative steps and does not know where the screen is, so absolute positions need care. It also ignores which device is in control, so the indicator and Stop button matter even more here.
- Use it only when the RemoteDesktop portal is missing, never as the first choice.

## Changes to the spec

None. Design §9.3 already uses the portal with a saved restore token, and `uinput` with a udev rule where the portal is missing. Two notes for the remote-control and screen-sharing tasks:

- Ask for `persist_mode` 2 and store the restore token in the keystore. Delete it with the other secrets.
- On a compositor without the portal, check `/dev/uinput` access before offering the udev rule.
